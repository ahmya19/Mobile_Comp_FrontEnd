## Resolution of open questions from `MobileComp_GROUP2.pdf`

Reading the Group 2 proposal resolves the two largest scope ambiguities from CP-45:
1. **Comments / replies with photos (PDF 5.2, 5.3, 8.2):** **Out of Spec.** `MobileComp_GROUP2.pdf` specifies report submission, interactive map, community feed, urgency voting, offline queue, smart photo upload, official status updates, push notifications, and SMS fallback — never comments or comment moderation. No unapproved comments schema was added.
2. **Multi-photo per report (PDF 3.3, 4.6):** **Out of Spec.** `MobileComp_GROUP2.pdf` specifies one compressed photo on mobile data plus one full-resolution original on Wi-Fi per report. Single-photo schema (`photo_path` + `original_path`) is retained.
3. **Camera capture (PDF 3.2):** **In Spec & Implemented.** `MobileComp_GROUP2.pdf` page 1 explicitly identifies the phone camera as a core reporting input. Implemented via `ActivityResultContracts.TakePicture` + private `FileProvider` (`camera_captures/`), runtime `CAMERA` permission denial handling, EXIF orientation + GPS stripping, and temp capture cleanup.
4. **SMS format reconciliation (PDF 8.6 vs deployed `sms.mjs`):** **Reconciled to deployed contract.** The in-app SMS Reporting Guide (`SmsGuideScreen.kt`) teaches the exact deployed single-segment GSM-7 format (`PIN <CATEGORY>;<BARANGAY>;<DESCRIPTION>`, <= 160 septets, Alangilan only) with live GSM-7 counter, clipboard copy, and explicit-consent `ACTION_SENDTO` handoff to the system Messages app (never silent send).
