# PinPoint offline submission contract

The app saves each submission to a private SQLite queue before attempting network work. The queue owns a stable UUID, Supabase user ID, project URL, immutable report fields, and a private JPEG copy; a temporary image-picker URI is not enough. The user approved implementing the mobile-owned queue as well as the backend on November 21, 2026.

Queue states are Queued, Sending, Synced and Failed. A network failure returns Sending to Queued; a server validation failure becomes Failed and keeps the error. Synced means `submit_report` acknowledged a committed database row, not merely that a photo uploaded. The success screen must distinguish device saving from server acknowledgement.

Workers run only with a network connection and the same signed-in user and project recorded in the queue. Signing into another account cannot submit someone else's drafts. WorkManager schedules retries; exact reconnect timing must be measured on a device and is not guaranteed by this contract.

Pending compressed report drains request expedited priority, with RUN_AS_NON_EXPEDITED_WORK_REQUEST if quota is exhausted. Account restoration creates no report drain without active-owner/project Queued or Sending rows: an empty ordinary predecessor could block a later urgent submission. Pending originals are scheduled directly under their separate unmetered rule. The legacy Android foreground notification contains no report/account details. The correction is verified locally and at the phone restoration/queue boundary. Timely delivery remains subject to device policy. On the TECNO, Android Unrestricted alone did not prevent an inherited kernel UID freeze. The separate Battery Lab No Restrictions setting allowed WorkManager recovery in 1.310 s awake and 1.337 s screen off from host-observed Wi-Fi availability; reverting the OEM policy reproduced delay. These are device-specific observations, not a universal scheduling guarantee. See [background setup](../ANDROID_BACKGROUND_SETUP.md) and [investigation](../BACKGROUND_SYNC_INVESTIGATION.md).

The private bucket is `report-images`; the object name is `<user UUID>/<report UUID>/photo.jpg`. Upload once with no overwrite. If an earlier attempt uploaded it, compare the stored bytes with the saved local bytes before reusing it. The database function requires the correct owner path and an uploaded object. Published evidence cannot be deleted or overwritten through client policies.

`submit_report` takes the stable UUID, category, description, text location, barangay, optional paired coordinates and optional photo path. Ownership, status and priority come from the server. A retry with the same owner and payload returns the existing record. Reusing the UUID with changed content or another account fails. Photo files can be removed locally only after a server acknowledgement.

An interrupted worker is allowed to repeat both steps; neither step may create a second report. The Android checkpoint test verifies an offline photo report across a force-stop and reconnection. This prototype test does not establish the proposal's statistical timing/loss targets.

SQLite schema version 2 adds original_file, original_mime, original_state and upload_url. The optional original is copied before enqueue acknowledgement, capped at 10 MiB, and restricted to JPEG/PNG/WebP. Its independent states are Waiting for Wi-Fi, Uploading on Wi-Fi, Uploaded and Failed. Synced still means the compressed report is committed; an original can remain pending afterward.

OriginalUploadWorker requires an unmetered connection and also checks an actual unmetered Wi-Fi transport. DNS and sockets bind to that Network; each chunk checks it again. A Wi-Fi loss fails that transfer instead of switching original bytes to cellular. TUS creates a persistent upload URL, HEAD retrieves the acknowledged server offset, and PATCH sends at most 6 MiB. A completed object with an uncertain acknowledgement is compared with the saved file. attach_original checks report ownership and object existence. Originals are immutable and readable only by the owner and assigned officials. Local originals are deleted after attachment acknowledgement.

The live Android transport test interrupted an upload after an acknowledged 6 MiB chunk, restarted the app, resumed the session, and compared the completed bytes. A separate queue test confirmed compressed sync on metered Wi-Fi, original deferral, and original completion after unmetered Wi-Fi returned. The available emulator has no active cellular network, so real Wi-Fi/cellular handoff measurements remain CP-25.
